# Security Policy

## Supported Releases

We actively maintain and provide security patches for the following major versions:

| Version | Supported          |
| ------- | ------------------ |
| 1.0.x   | :white_check_mark: |
| < 1.0   | :x:                |

## Reporting a Vulnerability

We prioritize the security and integrity of our embedded firmware, edge inference engines, kernel drivers, and telemetry daemons.

If you discover a potential security vulnerability within this repository or any related project:

1. **Do Not Open a Public Issue:** Please refrain from disclosing the vulnerability publicly via GitHub Issues or Discussions.
2. **Submit Details Privately:** Send a detailed security disclosure email to the maintainer:  
   `aravindreddy0726@gmail.com` or contact `DAravindReddy` directly via GitHub security advisories.
3. **Include Technical Specifics:**
   - Affected repository path and commit hash.
   - Exact steps or script to reproduce the vulnerability.
   - Proof of concept (PoC) if applicable.
   - Assessment of potential impact (e.g., privilege escalation, buffer overflow, credential leakage, denial of service).
4. **Response SLA:**
   - Receipt acknowledged within 48 hours.
   - Initial assessment and remediation timeline provided within 5 business days.
   - Coordinated vulnerability disclosure policy will be respected.

## Safe Harbor Policy

Security research conducted under this policy is considered authorized, and will not initiate legal action against researchers acting in good faith.
